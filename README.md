# 🦁 Guia Virtual do Zoológico (Totem Interativo)

Este repositório contém o software base para os totens de autoatendimento interativos a serem instalados nos recintos de um zoológico. O sistema utiliza Inteligência Artificial Generativa para responder perguntas dos visitantes sobre os animais de forma educativa, em tempo real, utilizando interações por voz.

## 📌 Status do Projeto e Notas de Implantação (Para Avaliação)

Este projeto é entregue como **Software Finalizado (Pronto para Implantação)**, aguardando definições de infraestrutura do cliente. Como esta versão está sendo avaliada em um ambiente de navegador (PC/Mobile) e não no hardware final do totem, algumas adaptações foram mantidas:

1. **Interface Híbrida (Voz/Texto):** O input de digitação (`st.chat_input`) foi mantido estritamente para facilitar os testes de homologação. No totem de produção, a interface será substituída por **interação 100% via voz** com botões físicos ou touch simplificado.
2. **Agnóstico a Provedores (Vendor Lock-in Free):** A arquitetura foi desenhada de forma modular e desacoplada. A escolha definitiva da LLM e dos modelos de TTS/STT (atualmente Groq e OpenAI) será parametrizada após a definição do orçamento de nuvem e requisitos de privacidade do cliente.
3. **Automação de Hardware:** A função de "Novo Visitante", atualmente acionada por um botão no menu lateral, será conectada aos **sensores de presença infravermelhos** do hardware final, limpando o contexto da conversa automaticamente quando o visitante se afastar do totem.
4. **Catálogo de Animais:** O arquivo `animals.py` atua como um *mock* (simulador de dados) da base principal. Em produção, este módulo será facilmente substituído por requisições a uma API ou consultas diretas ao banco de dados relacional do zoológico, mantendo o restante do sistema intacto.

## 🛠️ Tecnologias Utilizadas

A arquitetura foi desenhada priorizando velocidade (baixa latência para interação humana) e escalabilidade:

* **Interface e Framework:** [Streamlit](https://streamlit.io/)
* **Orquestração de IA:** [LangChain](https://www.langchain.com/)
* **LLM (Cérebro do Agente):** GPT OSS 120b (via Groq API) para latência ultrabaixa.
* **Speech-to-Text (STT):** Whisper Large V3 Turbo (via Groq API).
* **Text-to-Speech (TTS):** GPT-4o-Mini-TTS (via OpenAI API).
* **Banco de Dados (Telemetria):** [Supabase](https://supabase.com/) (PostgreSQL) gerindo *logs* de conversas e *feedbacks* de usuários.

## ⚙️ Arquitetura do Sistema

O código foi modularizado para separar a interface do usuário da lógica de negócios e de infraestrutura:

* `app.py`: Controla a interface visual, gestão de sessão e o fluxo principal de mensagens.
* `config.py`: Gerencia os *prompts* de sistema, instâncias com *cache* dos clientes de API e as funções de áudio (STT e TTS).
* `database.py`: Gerencia o *pool* de conexão única e autenticada com o Supabase, realizando inserções e atualizações de *feedback*.
* `animals.py`: Dicionário de dados contendo o catálogo de animais, emojis e nomes científicos.

## 🚀 Como Rodar o Projeto Localmente

### 1. Clonar o repositório

```bash
git clone https://github.com/matguifra/zoo-chatbot.git
cd zoo-chatbot
```

### 2. Criar o Ambiente Virtual e Instalar Dependências

```bash
# Windows
python -m venv venv
.\venv\Scripts\activate

# Linux/macOS
python3 -m venv venv
source venv/bin/activate

# Instalar os pacotes
pip install -r requirements.txt
```

### 3. Configuração do Banco de Dados (Supabase)

O projeto utiliza o **Supabase** (PostgreSQL) para gerenciar logs de conversas, telemetria de sensores e feedbacks. Para que o projeto funcione corretamente, você deve criar as tabelas e políticas de segurança (RLS) abaixo no seu editor SQL do Supabase.

#### Estrutura de Tabelas e RLS

Execute o seguinte script SQL para criar as tabelas `aproximacoes` e `conversas`, além de suas respectivas políticas:

```sql
-- Tabela de aproximações (telemetria do sensor)
create table public.aproximacoes (
  id bigint generated by default as identity not null,
  aproximacao boolean not null,
  timestamp timestamp with time zone not null default now(),
  constraint aproximacoes_pkey primary key (id)
) TABLESPACE pg_default;

alter table public.aproximacoes enable row level security;

-- Policies para aproximacoes
alter policy "insert wokwi interaction"
on "public"."aproximacoes"
to anon
with check (true);

alter policy "dashboard"
on "public"."aproximacoes"
to authenticated
using (
  (( SELECT auth.uid() AS uid) = '<user_id_dashboard>'::uuid)
);

-- Tabela de conversas
create table public.conversas (
  id bigint generated by default as identity not null,
  timestamp timestamp with time zone not null default now(),
  sessao uuid not null,
  modelo text not null,
  animal text not null,
  pergunta text not null,
  resposta text null,
  feedback boolean null,
  constraint conversas_pkey primary key (id)
) TABLESPACE pg_default;

alter table public.conversas enable row level security;

create index IF not exists idx_conversas_timestamp on public.conversas using btree ("timestamp" desc) TABLESPACE pg_default;
create index IF not exists idx_conversas_sessao on public.conversas using btree (sessao) TABLESPACE pg_default;
create index IF not exists idx_conversas_animal on public.conversas using btree (animal) TABLESPACE pg_default;

-- Policies para conversas
alter policy "chatbot insert"
on "public"."conversas"
to authenticated
with check (
  (( SELECT auth.uid() AS uid) = '<user_id_chatbot>'::uuid)
);

alter policy "chatbot update"
on "public"."conversas"
to authenticated
using (
  (( SELECT auth.uid() AS uid) = '<user_id_chatbot>'::uuid)
);

alter policy "dashboard"
on "public"."conversas"
to authenticated
using (
  (( SELECT auth.uid() AS uid) = '<user_id_dashboard>'::uuid)
);
```

#### Usuários Necessários

Para que as políticas de RLS funcionem, você deve criar **dois usuários** na aba de Autenticação do Supabase:

1. **Usuário Chatbot:** Responsável por inserir e atualizar os logs das conversas no totem.
2. **Usuário Dashboard:** Responsável por visualizar os dados de telemetria e logs (geralmente usado em uma interface administrativa separada).

> [!IMPORTANT]
> Após criar os usuários, substitua `'user_id_chatbot'` e `'user_id_dashboard'` no script SQL acima pelos UUIDs reais gerados pelo Supabase para cada usuário.

### 4. Configurar as Variáveis de Ambiente (Secrets)

Crie uma pasta chamada `.streamlit` na raiz do projeto e, dentro dela, um arquivo chamado `secrets.toml`. Preencha com as suas credenciais:

```toml
# Arquivo: .streamlit/secrets.toml

PASSWORD = "senha_de_acesso_ao_totem"
OPENAI_API_KEY = "sua-chave-aqui"
GROQ_API_KEY = "sua-chave-aqui"

[connections.supabase]
SUPABASE_URL = "https://seu-projeto.supabase.co"
SUPABASE_KEY = "sua-anon-key"

[credentials]
EMAIL = "email_do_usuario_chatbot@exemplo.com"
PASSWORD = "senha_do_usuario_chatbot"
```

### 5. Executar a Aplicação

```bash
streamlit run app.py
```

A aplicação abrirá no seu navegador padrão.

1. Digite a senha configurada.
2. Acesse as configurações e selecione qual animal este totem representará.
3. Inicie a interação com o guia!

---

> [!NOTE]
> Certifique-se de que o usuário configurado em `[credentials]` no arquivo `secrets.toml` tenha permissão via RLS para as tabelas `conversas` e `aproximacoes`. O código utiliza este usuário para realizar as operações de banco.
